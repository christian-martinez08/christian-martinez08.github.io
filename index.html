1. ¿Cómo crear un sitio web en GitHub Pages?

El presente manual describe los pasos metodológicos necesarios para desplegar un sitio web estático utilizando la plataforma de alojamiento GitHub Pages de forma segura y directa mediante URL:

Paso 1: Creación del Repositorio

Se debe iniciar sesión en la plataforma GitHub. A continuación, para crear el espacio de trabajo, diríjase a la esquina superior derecha y haga clic en el botón de opciones (ícono de suma +), seleccionando la alternativa New repository (Nuevo repositorio), tal como se visualiza en la siguiente imagen:

Si desea acceder directamente a la plataforma oficial para comenzar el proceso, puede hacer clic en el siguiente enlace: Plataforma oficial de GitHub.

Paso 2: Rellenar el formulario del Repositorio

Una vez completado el paso anterior, se visualizará el formulario de creación de un nuevo repositorio, tal como se observa en la siguiente imagen:

En este apartado se deben configurar los siguientes elementos clave:

  • 1. Nombre del repositorio: Se asigna el identificador del proyecto. Es importante considerar la estructura de la URL para asegurar un acceso correcto en las etapas posteriores.
  • 2. Descripción: Campo opcional que permite añadir una breve reseña sobre el propósito o contenido del sitio web.
  • 3. Visibilidad: Se selecciona el acceso público o privado de acuerdo con las necesidades de la práctica.
  • 4. Botón de guardado: Por último, se debe hacer clic en el botón verde inferior que confirma la creación del repositorio para registrar los cambios definitivamente.

Paso 3: Creación y subida del archivo principal (index.html)

Una vez creado el repositorio, le daremos a creating new file. Es necesario incorporar el código fuente que estructurará la página web. Para ello, se debe crear un archivo llamado estrictamente index.html en la raíz del repositorio.

Este archivo contendrá las etiquetas HTML necesarias y la información del manual, asegurando que el servidor lo reconozca automáticamente como la página de bienvenida principal al cargar la URL.

Paso 4: Activación de GitHub Pages y obtención de la URL segura

Para publicar el sitio en la web de forma accesible:

  • 1. Configuración: Diríjase a la pestaña de Settings (Configuración) en la parte superior derecha de su repositorio.
  • 2. Sección Pages: En el menú lateral izquierdo, busque y seleccione la opción Pages.
  • 3. Despliegue (Build and deployment): En el apartado de fuentes (Source), seleccione la rama principal (generalmente llamada main) y asegúrese de que esté configurada en la ruta raíz (/root), luego haga clic en guardar.
  • 4. URL final: Tras unos minutos, la plataforma generará la URL segura definitiva (por ejemplo, https://adara1234.github.io/), la cual podrá compartir para visualizar el sitio web completo.

¡Felicidades, has completado tu sitio web!

Siguiendo cada uno de estos pasos detallados, habrás logrado configurar y desplegar con éxito la estructura de tu sitio web en GitHub pages.

Con esto ya tendrías tu página completamente lista, funcional y accesible mediante la URL segura para presentar tu sitio web sin inconvenientes.

2. Modificadores de Acceso y Encapsulamiento en C# v5

¿Qué son y para qué sirven los Modificadores de Acceso?

Son palabras clave que definen la visibilidad y el nivel de accesibilidad de las clases y sus miembros (atributos y métodos). Sirven fundamentalmente para proteger la integridad de los datos, evitar modificaciones accidentales desde el exterior y controlar qué partes del programa pueden interactuar con la información.

  • Public: Permite el acceso sin restricciones desde cualquier otra clase o ensamblado.
  • Private: Restringe el acceso de manera exclusiva al interior de la clase donde se declara.
  • Protected: Otorga visibilidad a la clase contenedora y a sus clases derivadas (herencia).

Encapsulamiento de Clases: ¿Qué es y para qué sirve?

El encapsulamiento de clases es el principio fundamental de la programación orientada a objetos que consiste en agrupar en una sola estructura (la clase) tanto los datos (atributos) como las operaciones que actúan sobre ellos (métodos), ocultando el estado interno del objeto al resto del programa.

¿Para qué sirve? Sirve para blindar la información sensible, evitando que clases externas alteren los datos de forma incorrecta o corrupta. Su propósito principal es garantizar la seguridad y la modularidad del código, obligando a que cualquier consulta o modificación de los atributos privados se realice exclusivamente a través de métodos controlados y seguros definidos en la misma clase.

Ejemplo Práctico en C# v5

A continuación, se presenta un código estructurado que demuestra el uso de atributos privados encapsulados y métodos públicos de acceso en C# v5:

using System;

namespace ManualGitHubCSharp
{
    // Clase pública accesible desde cualquier módulo
    public class Persona
    {
        // Atributo privado (Encapsulado): Protegido contra modificaciones externas directas
        private string cedula;
         
        // Atributo protegido: Accesible en esta clase y sus clases derivadas
        protected int codigoInterno;
                
        // Atributo público: Accesible desde cualquier instancia
        public string Nombre;
       
        // Constructor para inicializar los valores de la clase
        public Persona(string nombre, string cedula, int codigo)
        {
            this.Nombre = nombre;
            this.cedula = cedula;
            this.codigoInterno = codigo;
        }

        // Método público para consultar el valor del atributo privado de forma segura
        public string ObtenerCedula()
        {
            return cedula;
        }
    }
}
